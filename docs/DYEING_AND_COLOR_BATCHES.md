# Dyeing and color batches

Create controlled colors through **نیا رنگ** on `/processing/color-batches`. Codes must be unique; colors have Urdu/English names and active status. Create a dyeing job, then allocate color batches with color, target meters, shade/sample reference and notes. Combined batch targets cannot exceed job inputs. For each batch, posted physical returns plus recognized loss cannot exceed its own input target, even when the overall job still has other colors outstanding.

A shade decision records approval, rejection or rework and the actor. Accepted dye output requires an approved matching batch and color. Rejected/pending shade can physically return into held or rejected custody, preserving ownership and traceability. Approved output cannot be retroactively relabeled by changing its batch decision; use QC on the actual output.

Each receipt can assign its line to a color/batch; use separate partial receipts when one issued line returns different colors. Output lots are distinct by receipt line and quality category, and retain color, batch, job and original lot lineage. The same issued quantity cannot be returned twice.

Batch distribution, actual output, rejected/held output and loss are derived from linked outputs and receipt parts. A batch is an operational planning/approval record, not a second inventory ledger. Full laboratory shade workflows and artwork/image APIs are outside this frontend phase.
